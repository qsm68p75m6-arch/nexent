# D02 图片轮排查链与路线决议（2026-11-11）

## 三次失败的完整排查链（同一文档，三种错误，三层根因）

| 时间 | 错误表现 | 层级 | 根因 | 处置 |
|---|---|---|---|---|
| 11-08 首次 | 解析失败（无细节） | 资源层 | ES 磁盘熔断 + Ray 内存保护杀解析进程 | 清构建缓存 17G、重启 ES、停 Langfuse 释放 3.5GB |
| 11-11 15:12 | 知识库入库服务暂时不可用 | 服务层 | data-process 崩溃后未恢复，上传撞上空窗 | 服务自动重启，Ray 池预热完成，日志验证四组 Worker 就绪 |
| 11-11 15:16 | 数据处理内核无法从文档中提取有效文本（请确保文档内容非纯图像） | 能力层 | **v2.7.0 入库管线只做文本提取，无 OCR** | 见下方路线决议 |

## 服务日志实锤（11-11 15:16 失败时的 data-process 日志）

```
ERROR [process-worker] Ray processing completed but produced 0 chunks
      {"error_code": "no_valid_chunks", "original_filename": "D02_ownership_diagram.pdf", ...}
WARNING [RayActor] file_process returned empty list for source='D02_ownership_diagram.pdf'
```

解析器对纯图像 PDF 提取出 0 个字符，全程无 OCR 尝试。**结论：原生路线判死——Nexent v2.7.0 知识库入库不支持纯图像 PDF。**

## 路线决议

1. **主轨（采用）**：textlayer 文字层版入库——图像信息以等价文字层形式进入知识库，解析与检索正常走文本管线。验收标准：解析成功 + 分片详情可见股权实体关系 + 依据 source_md 可答持股比例问题。
2. **亮点轨（补充演示）**：会话内直接上传原图给多模态模型读图——若平台支持，这是真·多模态理解的演示点（与 KB 管线无关）；不支持则记录为平台边界。
3. **不做**：给 data-process 更换 OCR 解析引擎（MinerU 等）——超出比赛周期，且破坏评测环境一致性。

## 遗留影响

- 赛题"多模态异构"要求中，图像模态在**知识库管线**内不可用（平台边界，已实证）；多模态能力由**会话内多模态模型**承担（待亮点轨验证）。
- 设计文档"调试迭代经验"素材链完备：服务层→资源层→能力层三层递进排查。
