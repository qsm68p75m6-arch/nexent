# 官方预置智能体设计 × 赛题评分对齐分析（2026-11-12）

> 数据来源：本地源码 11 个官方智能体的 agent.json 逐个实测提取（medical 6 + government 5，字段见附表）。
> 用途：把官方设计模式转成我们担保核验智能体的优化动作，并对齐初赛技术评分四维（各 25%）。
> 源文件打包：`nexent-official-agents-src.zip`（同目录，51 文件 / 21.2MB，已 gitignore 不入库）。

## 二、提炼出的 10 个官方设计模式（每条注明出处）

1. **三段式提示词**：职责（duty，约100-160字）+ 编号硬约束（3-8条）+ 少样本示例（few_shots 含"思考→代码→观察"全链路）。11 个全部如此。
2. **工具白名单反幻觉**：医保审查第 1 条"只能使用 knowledge_base_search，不得调用任何未授权工具"；社媒"仅使用已绑定工具"。反幻觉靠限定工具集，不靠模型自觉。
3. **先取证后结论**：肺CT诊断第 1 条"必须优先调用 analyze_image 提取结节特征，**严禁在未分析影像的情况下直接生成**结论"——和我们"结论绑定证据"执行流同源。
4. **缺证不编造**：病历生成第 5 条"工具返回为空或不完整，应提示用户补充，**不得自行编造**"。官方只在 1 个智能体里写了 1 条，且无实验验证——我们用 C05/T05 八轮受控实验把它实证了，这是差异化点。
5. **知识库索引硬绑定**：质控助手约束里写死"索引名称固定为[放射科影像诊断报告书写规范]"；招投标要求 index_names 必须显式指定。防检索漂移。
6. **权威文档当知识库**：病历书写与管理基本规范（2025版）、碘对比剂临床应用指南（第2版2026）、凝血障碍诊断规范——全是权威指南，无科普文。选材标准可直接抄。
7. **步数预算 = 复杂度路由的工程化**：判读/诊断类 5 步、生成类 15 步、评审类 30 步。
8. **Skill = 能力沉淀的载体**：docx 输出（病历）、web-scraper（举报）、xlsx 解析（安全报告第 1 条**强制**走技能）。
9. **纯技能编排可行**：网络安全报告助手零工具零 KB，纯靠 3 个技能完成——"能力沉淀"评分项的极端示范。
10. **子智能体编排**：血检专家的 `managed_agents` 展开出 2 个子智能体（血液报告解读、血液评估，平台 id 4/5）——主专家+专职子 agent 的官方实现。

## 三、对齐评分四维：官方做法 → 我们的差距 → 优化动作

### 维度 1：智能体编排与 MCP/Skill 深度集成（25%）

- 官方做法：KB+专用工具组合、skill 输出、managed_agents 子智能体。
- 我们现状：**单 agent 直接问答，零 MCP 零 Skill**（P4/P5 未启动）——这是当前最大的失分风险。
- **动作**：
  - **P0**：启动 P4 自研 MCP 计算器（单位归一/去重/口径检查）。赛题原文"MCP 协议核心机制"必须有实证，官方 11 个 agent 没有一个挂自定义 MCP——我们挂了就是超越官方的集成证据。
  - **P1**：照血检专家的 managed_agents 模式拆子智能体：规划 agent（生成核验清单）/ 计算 agent（调 MCP）/ 核查 agent（证据比对）。
  - **P1**：仿 create-docx 做"核验报告 docx 导出" skill——同时喂"能力沉淀"分。

### 维度 2：资产激活的业务价值（25%）

- 官方做法：描述里写业务人设（"拥有超过10年临床经验"）、权威指南当 KB。
- 我们现状：沪光 T 系列 10/10 已是比官方演示更硬的业务价值证据（官方 8 个 agent 一个实测数据都没有）。
- **动作**：**P0** 按三段式重构我们主 agent 提示词——duty 写"担保核验合规审查"角色定位，constraint 逐条写口径纪律（授权额度/发生额/期末余额三分、缺证保留、冲突并列、版本时效）。官方约束平均 5-8 条 300-600 字，我们现有 system prompt 远达不到这个精度。

### 维度 3：算法创新性（25%）

- 官方 11 个 agent **全部是工具编排演示，零算法创新**：没有缺证处理实验、没有冲突识别、没有版本回归、没有本体演化。
- 我们已有的 C/T 系列实验就是差异化本体——但要在文档里"显式对比"才能被评委看见。
- **动作**：**P0** 设计文档加一节"与官方预置智能体的对比"：官方缺证约束仅 1 条且未验证 vs 我们 8 轮实验+错误分析（引用 evidence/）。**P1** A5 本体演化对照实验（官方完全没有）。

### 维度 4：系统交互体验与能力沉淀（25%）

- 官方做法：few_shots 覆盖单文件/并行/多文件汇总/定制化输出 4 类任务场景；skill 交付可下载成果。
- 我们现状：无 few_shots，无可下载交付物。
- **动作**：**P1** few_shots 照官方格式补 4 类示例（单事项核验/跨文档冲突/版本回归/缺证保留各一，全链路"思考→检索→观察→结论"）；**P2** 结合 P1 的 docx skill 做交付闭环。

## 五、答辩防质疑备注

1. **"你们和官方预置有什么区别？"**——官方是演示级：8 个 agent 无一有实测数据、内置校验全关、缺证约束仅 1 条。我们是实验级：10/10 受控评测、失败案例分析、记忆串味发现与治理。同一平台，我们做到了官方没做的验证深度。
2. **"为什么借鉴官方写法？"**——平台原生范式（三段式提示词、managed_agents、skill 沉淀）保证兼容性与可维护性；在此之上做官方没有的算法创新与实验验证。借鉴工程范式 ≠ 创新缺失，评分维度 3 靠 C/T 系列实验支撑。
3. **注意联网工具**：肺CT诊断挂了 exa_search（联网）——我们评测一律禁联网，文档里可写"官方亦在受控场景外才用联网检索"，与我们"禁外部检索"的评测纪律一致。
