# 02 整体方案设计

## 已确认：三个创新点（2026-10-22 定）

1. **任务驱动的本体演化**（主算法创新，对应"算法创新性"25%）：业务问题决定优先补哪些知识。任务失败先归因四分：材料没找到 / 资料本来就缺失 / 证据冲突 / 现有本体表达不了；只有最后一类才产生本体修改候选。候选审核优先级综合：抽取结果分歧、影响业务问题数、与规范的冲突程度、预计人工审核成本。可验证命题：同样审核 20 个候选，按业务影响优先是否优于随机审核、仅按不确定性审核（A5 实验）。
2. **检索-推理闭环**：把业务问题拆成待验证条件，推理缺口映射四类动作——改写查询再检索 / 输出待补材料、保留判断 / 核查口径与版本（更正公告）/ 提交本体变更候选。检索与推理互相反馈。
3. **知识更新影响定位**：新公告或规范进入后，沿依赖关系找到受影响的事实、规则和已有结论，只对相关部分重新核验并保留历史版本。区分三种更新：事实更新、规则更新、本体结构更新。

## 已确认：执行流原则

- 检索-推理双驱动协同执行流（评分原话要求），每步结论绑定证据：文档标识、版本、页码 / 段落 / 表格单元格。
- 数值计算与规则检查交给确定性工具（P4 自研 MCP 计算器：单位归一、去重、口径检查），模型只负责问题拆解与解释。
- 每题独立会话、独立知识库绑定（C05 教训，见 docs/progress.md）。
