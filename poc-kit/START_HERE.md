# Nexent 小型可行性验证：从 3 道题开始

本包围绕“上市公司对外担保披露核验”设计逐轮实验。先用可控合成材料验证解析、检索、计算、缺证和时间版本，再用独立公开真实资料检查外部有效性，最后评估低资源本体演化。全部公司、事项和规则均为虚构测试夹具；本包没有证明真实行业效果，也没有证明算法创新优于已有方法。

本文中的通过门槛、题量、人工预算和轮次都是建议，不是赛题规定。具体评分要求仍以原始赛题为准。

## 现在就做的第一轮

你已经配置文字模型、Embedding 模型和多模态模型。先做文字对照，只运行 C01、C02、C05 三题，不需要一次完成全部实验。

1. 在 Nexent 建立两个独立知识库：`POC_TEXT_BASE` 和 `POC_TEXT_MISSING`。它们统称文字对照实验，`POC_TEXT` 不是要求平台具备的新对象类型。
2. 向 `POC_TEXT_BASE` 只导入 `source_md/` 中的 D01、D02、D03、D04 四份 MD。D02 的文字内容只供这组对照实验使用。
3. 向 `POC_TEXT_MISSING` 只导入 D02、D03、D04 三份 MD，禁止加入 D01。使用独立索引；不要依赖从已有库中删除 D01 来模拟缺证。
4. 等待两个知识库完成解析与索引。在当前界面允许的文档预览或检索功能中，核查 D03 的 G01、G02 两行，以及 D04 对 G01 的重复披露。记录实际显示的解析结果。
5. 先用最简单的问答 Agent。模型、提示词和检索参数固定；一次只绑定一个实验知识库，关闭联网搜索、其他知识库、跨题记忆及无关工具。建议提示词见 `agent_config/agent_prompt.txt`。
6. 在 `POC_TEXT_BASE` 中分别以全新会话询问 C01、C02；将库切换为 `POC_TEXT_MISSING`，再以全新会话询问 C05。题目原文见 `evaluator_only/questions.md`。
7. 将每次完整回答、引用来源、耗时和可见调用记录填入 `ROUND_LOG.md`。用 `evaluator_only/answer_key.json` 与 `evaluator_only/rubric.md` 核对；这些评测文件不导入平台。

这三题先确认：单项金额能否提取、能否处理单位和重复披露、授权材料缺失时能否保留判断。建议每题先跑 1 次，修复明显问题后固定配置再各跑 3 次。3 次重复只用于发现不稳定输出，不代表统计显著性或泛化能力。

第一轮需要交回的最少记录：3 个回答全文、3 组引用、使用的知识库名、模型名、每题耗时，以及失败时的检索或解析记录。不要只交截图中的最终结论。

G03 是否属于 A1 范围，由 A1 的明确持股门槛及股权图共同决定。40% 持股只能说明它不符合本测试授权的门槛，不能单凭该比例断言公司控制关系，更不能判定现实违法。结论应限定为“符合/超出给定授权口径”“证据冲突”或“证据不足”。

## 逐轮实验与停止标准

### 第 0 轮：保存可复现的环境

目标是确认实验条件，而不是更改部署。记录 Nexent 实际版本、容器状态、浏览器入口、文字模型、Embedding 模型、多模态模型、索引配置、模型温度、检索条数和超时设置。Embedding 模型改变时，应重新创建或重建对应索引，避免将不兼容索引混入比较。

- **通过建议：** 可以进入平台；三个模型已配置；能够看到一次实际解析/检索/回答调用记录；无明显连接或鉴权错误。
- **停止条件：** 模型调用报错、解析任务长期未完成、索引不可用、无法确认实际使用哪个知识库。先排查服务连接、模型配置、任务队列和日志，不调业务提示词。
- **边界：** 不改动用户已有业务知识库、不清理现有向量数据、不替换现有模型配置。本包实验使用新增隔离对象。

### 第 1 轮：文字对照，先检查数据与检索

执行前文的 C01、C02、C05。先查看必要事实是否被正确解析，再检查检索是否返回必要证据，最后评价回答。解析和检索故障不能用猜测答案补偿。

- **通过建议：** C01 金额及日期正确；C02 单位、范围、去重和快照正确；C05 没有凭空补出授权上限，并明确需要授权材料。
- **停止条件：** G02 的 25 百万元被当成 25 万元；重复计入 D04 或合计行；把旧年份余额相加；C05 直接使用其他题出现的 5,000 万元。
- **下一步：** 若数据正确但检索不全，只调整一个检索变量，例如检索条数或切片策略，再回归三题。若检索完整但计算错误，进入规则计算轮。

### 第 2 轮：真实图像输入与多模态证据

新建三个正式实验知识库；全部使用 `import_docs/` 的 PDF，不混入同内容 MD。

| 知识库 | 初始允许文档 | 题目 |
|---|---|---|
| POC_BASE | D01、D02、D03、D04 | C01—C04 |
| POC_MISSING | D02、D03、D04 | C05 |
| POC_CONFLICT | D01、D02、D03、D04、D07 | C06 |

D02 的 PDF 图片是本轮股权比例的唯一原始来源。不要将 D02 的文字对照、人工图注、答案、语义文件名提示或上轮对话放入本轮上下文。允许系统产生 OCR、图像描述或结构化关系，但需保存由哪张图片生成的记录。

先在图像解析结果中核对两条持股关系，再运行 C04。检查甲公司是否纳入、乙公司是否排除，以及结论是否同时引用图片证据和 D01 的范围条款。只上传了一张图片但没有用到其中的信息，不算完成图文推理验证。

- **通过建议：** 80% 和 40% 均正确识别；图片结果可追溯到 D02；C04 的范围判断正确；C01—C03 未因 PDF 解析退化。
- **停止条件：** 图片被跳过；只检索到标题；关系方向颠倒；答案来自文字对照库或残留会话。先检查模型路由、PDF 图片提取、OCR/视觉结果是否进入索引，再改提示词。
- **对照解释：** 文字轮通过而图片轮失败，说明图像解析或图文检索存在瓶颈，暂不能归因于业务推理算法。

### 第 3 轮：计算、规则、缺证与冲突

先将表格字段整理为结构化记录，最低包含事项 ID、担保主体、对象、统计日期、余额数值、单位、来源。用独立计算过程核对单位、去重和总额；可以先用手工核算或离线脚本，接入 MCP 后再转为工具调用。保存计算输入与结果，不能把模型的心算解释当成独立验证。

再按题运行 C01—C06，核对回答中的业务结论与证据是否一致。C05 不能仅回答“缺少资料”而不说明缺少授权范围/额度等哪项条件；若声称某个范围内余额可算，应能回指题干或 D03 中明确给定的口径，不得从缺失的 D01 偷用范围定义。C06 不能任意选取较新、金额更大或更可信的一条记录，也不能取平均值。

- **通过建议：** 所有受控的单位、去重、范围与金额计算准确；C05 正确保留判断；C06 明确指出 G01 的 3,000 与 3,200 万元冲突，拒绝给出未经消解的唯一精确总额。
- **停止条件：** 缺证被当成不存在审批；冲突被自动当成更正；正确答案没有支持证据；引用了不支持结论的表格行。
- **下一步：** 固定配置，每题新会话重复 3 次。逐题报告成功次数，例如 2/3；不要只报总体均值掩盖缺证题失败。

### 第 4 轮：版本更新及历史回归

只向 `POC_BASE` 新增 D05、D06，等待索引完成后运行 C07，并回归 C01—C04。旧文档保留，不覆盖 D01 或 D03。

- **7 月真值：** 2026 年 7 月 31 日范围内余额 5,500 万元，适用上限 8,000 万元，余量 2,500 万元。
- **6 月回归：** 2026 年 6 月 30 日仍适用上限 5,000 万元，超出 500 万元。
- **通过建议：** 两个日期均正确，引用相应版本；没有把不同日期余额合并；新增文档后旧题无退化。
- **停止条件：** 最新规则覆盖全部历史；只因文档发布日期新就替换旧事实；无法解释生效时间。先检查时间字段、版本筛选和查询约束。

### 第 5 轮：解除事件与本体演化判定

向 `POC_BASE` 新增 D08，运行 C08，并回归 6 月、7 月的问题。8 月 1 日 G02 已全部解除，G01 未变且无其他范围内变化，因此当日范围内余额为 3,000 万元；历史上 G02 及其旧余额继续保留。

记录本题失败的实际原因：解析、检索、单位/计算、时间规则、事实缺失、证据冲突，或本体无法表达。只有最后一类才提交本体结构变更候选。

如果现有本体已经能表达解除对象、生效日期和历史状态，只更新事实即可。如果不能，再提出“解除事件—作用于—担保事项”等最小结构补充，记录理由、依赖和回归结果。不得为了展示创新而强制新增类型或关系。

- **通过建议：** 新余额与旧时间点答案全部正确；能够说明余额变化来自哪个事项；修改类型判定有依据。
- **停止条件：** 直接删除 G02；解除公告被当成新增金额；将其与已更新的余额再次相减；没有业务错误却扩大本体。

### 第 6 轮：独立 MCP / Skill 通路

这一轮可以新增隔离的测试服务，先做一个输入输出明确的计算工具，再扩展证据定位或规则核验。建议最小工具职责为：输入结构化余额记录及查询日期，返回归一化记录、去重依据、总额、缺失字段和错误信息。不得读取评测答案文件。

先单独调用工具验证已知输入，再让一个 Skill 通过 Nexent 调用它。Skill 应写明输入、输出、工具依赖、适用条件、缺证处理与失败处理。保存实际调用链，证明请求确实经过 MCP 和 Skill，而非模型直接生成同样的答案。

- **通过建议：** 单独工具调用与平台调用结果一致；至少一次正常、一次缺字段、一次服务错误均有可见处理；C02、C05 通过；无无关数据访问。
- **停止条件：** 连接可见但没有实际调用；模型绕过工具给出数字；工具错误被包装成成功答案。
- **当前状态：** 本方案没有将该通路记为已跑通；地址、接口名、工具注册方式和平台兼容性需在实际实施时核实。

### 第 7 轮：独立公开真实资料

在合成机制过关后，另建 `REAL_PUBLIC`，先选择少量公司、约 5—10 个担保事项包，准备 12—20 道需跨文档回答的问题。每包检查是否有真实公告、余额表、授权依据、股权图或扫描页；至少纳入一个真实补充或更正事件。资料不完整的事项适合测试缺证，不应硬补答案。

人工制作来源清单与答案依据，按公司或事项整体划分开发与测试。保留真实 PDF 原文、披露日期、规则适用期、下载入口和证据位置。术语和规则应按案例当期适用规范核验，受控夹具中的持股门槛和额度不能照搬到真实案例。

- **通过建议：** 每道测试题的关键真值可人工复核；分别报告检索证据覆盖、计算正确、引用支持、缺证保留及核验耗时；所有失败可追踪。
- **停止条件：** 答案依赖未取得的内部材料；公开文档缺页；后续处理结果提前进入历史查询上下文；把合成规则当成法律依据。
- **结论边界：** 这一小规模实验用于发现外部失效因素；尚不能宣称达到行业级准确率。






### 第 8 轮：验证低资源本体演化是否有收益

冻结初始本体和历史回归题，再使用独立开发资料产生候选变更。先排除能够通过事实补充、检索修复或规则更新解决的问题，再比较随机审核、按不确定性审核、按业务影响审核三种候选选择策略。

各策略采用相同可审核候选数、人工审核流程、模型版本和总调用预算；同时记录人工分钟数与实际 token/调用量。可从每组 5 个候选的可执行小预算开始，但候选不足或样本过少时只报告过程，不推断算法优劣。每组从同一初始本体重新开始，不能顺序继承另一组的修改。

在未参与候选生成的新事项上测试收益，并回归历史题。记录候选接受率、概念/关系及标准映射准确性、业务问题正确数变化、审核时间和旧题退化数。调用预算耗尽时应一致停止，不给某组追加资源。

- **通过建议：** 实验可复现；审查预算与调用预算可比；存在独立测试与历史回归；能明确说明哪些收益来自结构变更。
- **停止条件：** 根据测试答案生成候选；只展示新增概念数量；只比较不同调用量的模型结果；结构变更未产生可验证作用。
- **结论边界：** 当前 8 道题只适合调试机制。算法提升与学术原创性需要更大的独立数据、对照实验和文献比较。

## 每次只改一个因素

每轮采用“固定版本 → 执行 → 定位失败层 → 单因素修改 → 重跑失败题 → 回归已通过题”。不要同时更换模型、Embedding、切片、检索条数、提示词和本体，否则无法解释提升来源。

优先级依次为：数据解析正确 → 必要证据检索完整 → 计算与规则正确 → Agent 调度与表达 → 本体结构优化。若真实图像输入未过关，先修图文链路；若证据完整而规则明确，先把计算移交确定性工具。

## 评测泄漏与结果表述

- 评测题、真值、日志、评分标准不得进入知识库、Agent 记忆、MCP 可读目录或检索元数据。
- 每题使用新会话，知识库和工具必须与本题证据包一致。特别检查 C05 是否能通过其他库、联网或历史对话看到 D01。
- 同一事项的改写、重复披露、更正公告及同源表格应整体划分开发/测试，不能仅按文件随机切分。
- 历史查询只能使用当时允许的信息；后续回复可供人工核对，但不得提前提供给被测系统。
- 测试集冻结后不据此调整提示词、规则或本体。调试过的题应标为开发题，并建立新的独立测试。
- 分别报告文字对照、图文轮、合成案例、公开真实资料和模拟变更结果，不混成一个准确率。
- 输出准确的分子/分母和失败类型。小样本 3 次重复是稳定性观察，不足以证明算法显著提升。
